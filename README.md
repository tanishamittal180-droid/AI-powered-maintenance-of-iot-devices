# Sentinel PM — AI-Powered Predictive Maintenance for IoT Devices

A portfolio-ready predictive-maintenance demo with a polished Streamlit operations dashboard, synthetic IoT telemetry, a scikit-learn Random Forest model, interactive Plotly analytics, virtual sensor simulation, CSV exports, and an optional Flask prediction API.

> **Important:** No industrial hardware or real failure dataset is included. Telemetry and failure labels are synthetic and intended for education/demo use. This is not validated for real-world maintenance or safety-critical decisions.

## Features

- **Overview dashboard:** fleet health, latest asset readings, sensor trends, health distribution, watchlist.
- **Live Monitor:** generate virtual readings under normal, elevated-load, or degradation scenarios.
- **Failure Predictions:** configurable risk threshold, sensor risk map, flagged-reading export.
- **Analytics:** sensor trends, per-asset label rates, correlation heatmap, distributions.
- **Dataset Explorer:** filter by asset/label, inspect missing values, export CSV.
- **Model Center:** train/retrain Random Forest, view accuracy/precision/recall/F1/ROC-AUC, confusion matrix, feature importance, and test custom readings.
- **Optional Flask API:** `/health` and `/predict`.
- Local-first setup; no API key, cloud account, GPU, or hardware required.

## Quick start — Windows

1. Install Python 3.10 or newer and Git.
2. Extract this ZIP and open the `AI-Predictive-Maintenance-IoT` folder in VS Code.
3. Open VS Code Terminal and run:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m src.generate_dataset
streamlit run main.py
```

If PowerShell blocks activation, use Command Prompt and run `.venv\\Scripts\\activate.bat`. You can also run `.\.venv\Scripts\python.exe -m streamlit run main.py` without activating.

Open the local URL printed in the terminal, usually `http://localhost:8501`.

## Quick start — macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m src.generate_dataset
streamlit run main.py
```

The app also creates the dataset automatically on first launch if it is missing.

## Train and evaluate

1. Start the dashboard.
2. Select **Model Center** from the left sidebar.
3. Click **Train / retrain model**.
4. Review metrics, confusion matrix, and feature importance.
5. Use **Test a custom reading** to explore predictions.

The model is saved locally to `models/predictive_maintenance_model.joblib`. Model files are ignored by Git by default; users can reproduce them by training locally.

## Optional REST API

Train the model in the UI first, then open a second terminal in the project folder:

```bash
python api.py
```

Health check: `GET http://127.0.0.1:5000/health`

Prediction: `POST http://127.0.0.1:5000/predict`

Example JSON:

```json
{
  "temperature": 74.0,
  "vibration": 3.8,
  "current": 11.0,
  "pressure": 2.6,
  "load": 0.85,
  "age_days": 900
}
```

Example response:

```json
{
  "asset_status": "failure_risk",
  "predicted_failure": 1,
  "failure_probability": 0.73,
  "note": "Demo prediction based on synthetic training labels; not for safety-critical use."
}
```

The numeric probability varies with the generated data and fitted model; the sample above is illustrative.

## Dataset and label design

`src/data_utils.py` creates timestamps, four simulated assets, asset age, load, temperature, vibration, current, and pressure. A small amount of missing sensor data is intentionally introduced to demonstrate preprocessing. The `failure` label is generated by a synthetic rule based on abnormal sensor signals and degradation. The model learns this simulated relationship, so a high test score does **not** prove real-world predictive accuracy.

To regenerate the CSV:

```bash
python -m src.generate_dataset
```

CSV path: `data/generated/iot_sensor_data.csv`.

## Limitations and next steps

- Data is synthetic; replace it with a properly documented public industrial dataset for stronger research.
- Use chronological or machine-wise validation for time-series deployment to reduce leakage risk.
- Calibrate probabilities and select alert thresholds based on operational costs.
- For real hardware, implement secure ingestion, sensor calibration, authentication, logging, and fail-safe controls.
- Do not automatically stop motors or machinery based only on this demo model.
